# Готовый промпт для Claude Code

Скопируйте текст ниже в Claude Code после распаковки ZIP в корень проекта сайта.

Нужно заменить только существующий блок «Контакты» на готовый блок из папки `contact-section-package`. Сначала изучи структуру и стек текущего проекта, найди текущий компонент/секцию контактов и способ отправки его формы. Не меняй header, логотип, верхнюю навигацию, footer и другие секции сайта.

Используй как источник:

- `contact-section-package/contact-section.html` — эталон разметки;
- `contact-section-package/css/contact-section.css` — эталон внешнего вида и адаптива;
- `contact-section-package/js/contact-section.js` — эталон валидации и отправки;
- `contact-section-package/assets/contact-background.png` — обязательное фоновое изображение;
- `contact-section-package/README.md` — пояснения по интеграции.

Сделай следующее:

1. Перенеси блок в текущий стек проекта. Если проект использует React/Next/Vue/Svelte, преобразуй HTML в нативный компонент этого фреймворка (`class` → `className`, корректные SVG-атрибуты, обработчики и состояние формы), а не подключай HTML через `innerHTML`.
2. Скопируй `contact-background.png` в штатную публичную папку проекта и исправь путь в стилях с учётом сборщика. Не оптимизируй и не обрезай исходный PNG без отдельного согласования.
3. Сохрани визуальную композицию desktop 1:1: заголовок по центру, прозрачные поля внутри центральной стеклянной панели изображения, зелёная кнопка, контакты слева, четыре преимущества справа и стеклянная панель «Нам доверяют» снизу.
4. Не добавляй логотипы компаний с референса. Оставь контейнер логотипов пустым либо подключи только те реальные логотипы, которые уже явно присутствуют в проекте как клиентские. Ничего не выдумывай.
5. Сохрани мобильную перестройку из CSS: до 900 px фото сверху, затем читаемые стеклянные карточки. Не допускай горизонтального скролла.
6. Подставь реальные контактные данные из текущей версии сайта. Если каких-то данных нет, оставь значения из шаблона и перечисли их мне как требующие подтверждения; не выдумывай новые контакты.
7. Подключи форму к уже существующему серверному endpoint/CRM проекта. Если обработчика в проекте нет, оставь интерфейс и валидацию рабочими, но не добавляй секреты в клиентский код; сообщи, какой server-side endpoint нужно создать. Поля: `name`, `phone`, `email`, `message`. Сохрани honeypot `website`, состояния загрузки, успеха и ошибки.
8. Сохрани доступность: связанные `label`, `aria-live`, клавиатурный focus, семантические `address`, `aside`, `section`, и корректные `alt` у будущих логотипов.
9. Избегай глобальных CSS-правил. Все новые стили должны оставаться внутри `.pb-contact` либо CSS Module текущего компонента.
10. Удали старую секцию контактов только после подключения новой. Не удаляй общие компоненты или API, которые используются в других местах.
11. Запусти штатные проверки проекта (lint/typecheck/test/build) и локально проверь минимум ширины 1537, 1280, 900, 768 и 390 px. Исправь найденные переполнения и ошибки сборки.

После работы покажи:

- список изменённых файлов;
- где теперь лежит фоновое изображение;
- куда уходит форма;
- какие контактные данные или логотипы ещё нужно передать;
- результаты lint/typecheck/build.
